# Spotify: how the homily audio actually gets there

## The short version

**There is no public Spotify API that uploads an MP3 episode to a
Spotify account.** Any code that claims to do
`spotify.upload(episode.mp3)` — including plausible-looking Spotipy
examples — does not work against the real API.

What exists instead, and what this repo implements, is the podcast
route Spotify itself uses:

```
homily.mp3 --copy--> a publicly served folder (HTTPS)
           --episode added to--> podcast RSS feed (feed.xml)
           --feed submitted once to--> Spotify for Podcasters
           --Spotify polls the feed--> new episodes appear automatically
```

## Why (verified)

- "Spotify is not a cloud hard drive or a file repository. It doesn't
  allow you to upload your MP3 episode directly... Spotify acts as a
  directory that reads information from an RSS feed generated by your
  podcast hosting service." — and the short answer to "can you upload
  the file to Spotify?" is no: Spotify only indexes and plays what is
  already published on your hosting.
- "Spotify does not offer an equivalent [publishing API] for podcast
  content. There is no public endpoint that lets an external service
  publish... to your show's Spotify page outside of the episode feed
  itself."
- The Spotify Web API can add items **that already exist in the Spotify
  catalog** to playlists and libraries. A brand-new homily MP3 is not
  in the catalog, so there is nothing for that API to add.
- Spotify "Local Files" is personal playback on one device only.
  Friends/followers cannot stream your local files, and it is not a
  publishing channel.

## What this repo does (src/spotify_rss.py)

When `ENABLE_SPOTIFY=true`:

1. Copies the finished homily MP3 to `PODCAST_AUDIO_DIR` atomically.
2. Adds/replaces the episode in `PODCAST_FEED_FILE`:
   title, description (the blog excerpt), Sunday `pubDate` in the
   parish timezone, a stable GUID (`oloj-<service>-<slug>`), and an
   `<enclosure url="PODCAST_AUDIO_BASE_URL/<file>.mp3" ...>`.
3. Re-running is safe: the same GUID replaces itself instead of
   duplicating the episode.

The MP3 and the feed **must be reachable over public HTTPS** — Spotify's
servers have to fetch them. A file sitting only on the laptop, or only
inside Dropbox with a private link, will not be ingested.

## One-time setup (a person does this once)

1. Put `PODCAST_AUDIO_DIR` / `PODCAST_FEED_FILE` somewhere public:
   the parish web host is the natural place (e.g.
   `https://www.ourladyofjoy.org/homilies/audio/` and
   `https://www.ourladyofjoy.org/homilies/feed.xml`), or any podcast
   host that lets you manage your own feed/files.
2. Prepare show artwork: 3000 x 3000 px JPG/PNG, and set
   `PODCAST_ARTWORK_URL`, `PODCAST_TITLE`, `PODCAST_DESCRIPTION`,
   `PODCAST_CONTACT_EMAIL` in `.env`.
3. Run the pipeline once so `feed.xml` exists with at least one episode.
4. Go to <https://podcasters.spotify.com> → "Add your podcast" →
   paste the feed URL → verify ownership (email to the contact address
   in the feed) → submit.
5. After that: **nothing manual**. Each Sunday run adds an episode to
   the feed, and Spotify (and Apple Podcasts, if you submit the same
   feed there) picks it up within a few hours.

## If you use a podcast host with a real API instead

Hosts such as Buzzsprout / Transistor / Libsyn offer their own upload
APIs and generate the feed for you. If Our Lady of Joy adopts one,
replace `src/spotify_rss.py` with a client for that host's API and keep
the rest of the pipeline unchanged — the pipeline only needs
"publish this MP3 + title + description + date" at that seam.
Spotify delivery still happens via that host's RSS feed.
